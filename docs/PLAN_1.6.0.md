## 1. 總覽

1.6.0 的主題是「**無字的漁港**」：除了收線小遊戲，畫面上不再出現任何文字。玩家只靠看、靠聽來判斷：魚池的魚餓了會浮上來張嘴，魚簍滿了會鼓起來，潮汐看潮汐鐘，漁販想要什麼就掛在他的扁擔上。

這是 2026-11-17 定下的系列規則（「除了釣魚小遊戲，其他都不能有任何文字提示，只能靠畫面與特效聲音判斷，追求沉浸式」）。同一天，烘焙、樂牧、草本已經把工作站的文字提示拿掉，收穫本來就沒有。漁歌的工作站從 1.4 起就只用聲音拒絕（`util/hint.js`），所以 1.6 要處理的是剩下的：手帳、魚池清單、魚簍清單、物品說明、觸控按鈕的字。

## 4. 無字規則

### 4.1 規則

> **除了收線小遊戲，漁歌不在畫面上顯示任何文字。** 玩家只靠模型、粒子、聲音與圖示判斷。

「顯示文字」指的是：

- `setActionBar`、`setTitle`、`updateSubtitle`、`sendMessage`，以及 `title`、`tellraw`、`say`、`msg` 指令；
- 表單（`ActionFormData`、`ModalFormData`、`MessageFormData`）裡的標題、內文與按鈕文字；
- 物品說明（lore）裡的字；
- 實體的互動按鈕文字（`interact_text`）；
- 掛在實體上的名牌（`nameTag`），除非是玩家自己用命名牌取的名字。

### 4.2 例外：收線小遊戲

收線小遊戲照舊用 actionbar 畫水道、魚與進度條（`fishing/minigame.js`、`fishing/rod.js`），不改。和它直接相關的也算在例外裡：

| 項目 | 處理 |
| --- | --- |
| actionbar 的水道與進度條 | 照舊 |
| `/scriptevent kaleidoscope_fishing:minigame …` 的回覆 | 照舊。這是管理員打指令時的回應，玩家平常看不到 |
| 手帳設定頁（字元樣式、管理員開關） | 照舊有字。它只設定小遊戲本身（2026-11-18 定案，見 22.1） |

### 4.3 不算提示、保留的

| 項目 | 原因 |
| --- | --- |
| 物品、方塊、實體的名稱 | 遊戲自己顯示，附加包拿不掉；也是三種語言玩家辨認東西的基本方式 |
| 森羅廚房圖鑑裡的「漁歌」分頁 | 是森羅廚房的書，玩家自己打開來讀；漁歌只是把頁面登錄進去（`kc/guidebookPublisher.js`）。豐收也是同樣的做法（2026-11-18 定案保留，見 22.1） |
| 內容日誌（`console.warn`、`console.info`） | 只有打開創作者設定才看得到 |
| 符號：◆ ✿ ✦ ★ | 不是字，任何語言都一樣 |

### 4.4 檢查

`tools/validate.py` 新增一項「無字檢查」：

- 腳本裡出現 4.1 的任何一個 API 或指令就失敗，**只放行** `fishing/minigame.js`、`fishing/rod.js` 的 actionbar 與 `fishing/minigameSwitch.js` 的指令回覆、`journal/journal.js` 的設定頁。
- 表單的 `title`、`body`、`button` 只能用「圖示字元」（第 5 節）或空字串。
- `setLore` 的內容只能是符號與圖示字元。
- 實體檔裡不能有 `interact_text`。
- 語言檔裡給上面這些用的鍵（`journal.*`、`pond.*`、`habitat.*`、`ing.*`、`lore.*`、`action.interact.kfv_*`）移除後，驗證工具確認沒有程式再引用它們。

樂牧在 2026-11-17 已經把同樣的檢查加進 `tools/validate.mjs`，漁歌照它的範圍做。

## 5. 基礎：圖示字元

### 5.1 為什麼需要

表單的按鈕與物品說明只能放字串。要在那裡放「圖」，基岩版的做法是**自訂字型的圖示字元**：資源包的 `font/glyph_E1.png` 是一張 16×16 格的圖，每一格對應一個私用區字元（``～``）。字串裡寫這個字元，遊戲就畫出那一格的小圖。原版的手把按鍵圖示就是這樣做的。

這樣表單與物品說明裡就能放「魚的小圖」「太陽」「月亮」「漲潮」這類圖，而不是字。

### 5.2 字元表

| 頁 | 範圍 | 內容 | 數量 |
| --- | --- | --- | --- |
| `glyph_E1` | `E100`–`E1FF` | 60 種漁獲 + 4 條傳說魚的小圖；「沒釣過」的魚影 | 65 |
| `glyph_E2` | `E200`–`E2FF` | 水域 18 種；時段（白天、夜晚、清晨、傍晚）；天氣（晴、雨、雷雨）；潮汐（漲、退、平）；月相 8 種；天象 2 種 | 約 40 |
|  |  | 鍋具與工作站（炒鍋、湯鍋、蒸籠、竹匾、魚案板、曬魚架、魚露甕、木盆、熔爐等） | 約 14 |
|  |  | 餌與釣具：12 種鉤線浮標、常用餌 | 約 20 |
|  |  | 數字點：一到五個點、「×」、勾、叉、箭頭、飼料碗（滿、半、空） | 約 15 |
| `glyph_E3` | `E300`–`E3FF` | 料理 102 道與食材（森羅廚房與原版的常用食材） | 約 150 |

- **不用重畫**：魚、料理、食材、釣具的小圖由 `tools/` 新增的腳本從現有的物品圖示縮成 16×16 再排進字元表，圖示改了就重新產生。水域、時段、潮汐、月相這類約 40 個符號是新畫的。
- 一頁最多 256 個，`glyph_E3` 不夠時用 `glyph_E4`。
- 字元表的對應寫在 `tools/data/GLYPHS.json`，由 `build.py` 產生 `scripts/data/glyphs.js`，腳本只用名稱取字元，不寫死碼位。

### 5.3 和其他附加包撞號

私用區沒有登記制度，另一個附加包也可能用 `glyph_E1`。兩個資源包同時有同一頁時，後載入的會蓋掉前面的。

- 先查森羅廚房、草本、樂牧、豐收、烘焙有沒有用到 `font/glyph_*.png`；有的話避開它們用的頁，並在 `docs/API.md` 寫下漁歌占用的頁，讓家族之後也避開。
- 原版用了 `glyph_E0` 與 `glyph_E1` 的一部分（手把圖示）。**實作前要在遊戲裡確認 E1 有沒有被原版占用**，被占用就整體往後移一頁。

## 6. 手帳改成繪本

手帳照舊是一本拿在手上打開的書，翻頁聲照舊；只是每一頁都只有圖。

### 6.1 首頁

| 1.5.0 | 1.6.0 |
| --- | --- |
| 標題「漁歌手帳」 | 不顯示標題（表單標題留一個看不見的標記，見 6.6） |
| 「已釣到 N / 60 種」 | 一條 60 格的魚影帶，釣到的魚亮起來 |
| 分頁按鈕（文字） | 分頁按鈕只放圖示：每個分頁用自己代表的水域圖 |
| 食譜、潮汐、設定（文字按鈕） | 食譜用鍋子圖、潮汐用潮汐鐘圖、設定用齒輪圖 |

### 6.2 分頁（10 頁）

- 每條魚一格：釣過的顯示魚的圖示；沒釣過的顯示黑色魚影（形狀看得出是大魚、小魚、蝦還是蟹）。
- 「N / M」換成那條魚影帶。

### 6.3 魚種頁

1.5.0 的棲息地說明是一段文字（例：「河流、湖泊；白天；雨天較多」）。1.6.0 改成一排圖示字元，每一類一格：

| 類別 | 圖示 | 來源 |
| --- | --- | --- |
| 水域 | 該魚會出現的水域圖，最多 4 個 | `CATCHES.json` 的 `waters` |
| 時段 | 太陽／月亮／兩個都有 | `CATCHES.json` 的時段條件 |
| 天氣 | 雨、雷雨（沒有條件就不放） | 同上 |
| 潮汐 | 漲潮／退潮（沒有條件就不放） | 同上 |
| 月相 | 該魚在意的月相（沒有條件就不放） | 同上 |
| 天象 | 流星、極光（只有天象魚） | `sky` |
| 釣竿 | 最低需要的釣竿圖 | `RODS.json` |
| 喜歡的餌 | 最多 3 個餌的圖 | 餌的資料 |
| 釣過幾次 | 1～5 個點，超過 5 次是滿的五個點加一顆星 | 釣魚紀錄 |
| 最大尺寸 | ◆／◆◆／◆◆◆ 中最大的那一級；破過紀錄加 ★ | 釣魚紀錄 |

- 圖示從資料表產生，不再寫 60 條 `habitat.*` 說明；新魚或外部註冊的魚只要資料齊全就自動有。
- 最大尺寸的公分數不再顯示。要看實際的長度，做魚拓（第 14.1 節）：魚拓上的魚依紀錄的長度畫出大小。

### 6.4 食譜頁

1.5.0 的食譜頁：料理名、鍋具名、食材清單（文字）、份數。

1.6.0：

- 列表頁：102 道料理的圖示；還沒學會的是一張碎紙片（和現在一樣的 `kfv_recipe_scrap`）。
- 料理頁只有一行：**鍋具圖 ＋ 食材圖 ×數量 → 料理圖 ×份數**。
  - 例：炒鍋 ┃ 牡蠣 ×2、蛋、生菜、麵粉 → 蚵仔煎。
  - 「×2」用點數表示：●● 就是兩份。
- 撿到食譜碎紙片時，翻開的頁面同樣是這一行。
- 食材中的森羅廚房物品沿用森羅廚房自己的圖示縮小。

### 6.5 潮汐頁

| 1.5.0 的文字 | 1.6.0 |
| --- | --- |
| 現在是漲潮／退潮 | 潮汐圖（漲、退、平） |
| 月相 | 月相圖 |
| 今晚的天象 | 傍晚以後出現流星或極光的圖；沒有天象就不放 |
| 漁販今天想收 | 漁販的頭像 ＋ 兩條魚的圖 |
| 訂單與進度 | 訂單魚的圖 ＋ 進度點（例：●●●○○ 是 5 條交了 3 條）；交齊是一個勾 |
| 三行說明（漲潮好釣、退潮挖蛤、新月出冰湖主） | 拿掉。這些知識改由魚種頁的圖示表達 |

潮汐鐘、天空本身就能看出潮汐與天象，潮汐頁只是整理在一起。

### 6.6 表單要怎麼做到「只有圖」

`ActionFormData` 的標題、內文、按鈕本來就接受字串，放圖示字元就是圖。剩下兩個問題：

1. **表單外框的標題列**：標題不能完全不給。給一個空白字元，外框上就只有一條空的標題列。
2. **按鈕排版**：原版表單的按鈕是一列一個、圖示在左邊。魚種、料理一頁 60～102 個，一列一個會很長。

兩種做法，見第 22.2 節第 5 項：

| 做法 | 怎麼做 | 好處 | 壞處 |
| --- | --- | --- | --- |
| **A. 自訂表單外觀**（建議） | 資源包加 `ui/server_form.json` 的修改：標題是某個看不見的標記字元時，改用格子排版（像背包），每格只有圖示 | 像一本真正的圖鑑；一頁看得到全部 | 其他附加包也改 `server_form.json` 時會互相蓋掉，森羅廚房自己有沒有改要先查 |
| **B. 原版表單** | 不改外觀，按鈕文字只放圖示字元 | 不會和其他附加包衝突 | 一列一個，翻 102 道料理很長；可以分頁（每頁 20 個，左右箭頭圖示翻頁） |

A 不成時用 B 當保底，兩者的腳本相同，只差資源包的外觀檔。

### 6.7 和森羅廚房圖鑑的分工

森羅廚房圖鑑的漁歌分頁（`GUIDEBOOK_JSON.json`）照舊。它是另一本書，有完整的說明文字。手帳是隨身的圖，圖鑑是坐下來讀的書（2026-11-18 定案保留）。

## 10. 拒絕與狀態的聲音語言

1.5.0 的 33 種拒絕原因都是同一聲低音（`note.bass`，音高 0.7）。只聽聲音，玩家分不出是「放錯東西」還是「還沒好」。1.6.0 分成四種，每種一個聲音加一個粒子，整個系列用同一套（烘焙、樂牧的拒絕之後也照這四種調整）：

| 類別 | 意思 | 聲音 | 粒子 | 1.5.0 的原因 |
| --- | --- | --- | --- | --- |
| **缺東西** | 手上的東西不對，或少了某樣 | `note.bass`，音高 0.7（現在的聲音） | 在方塊上冒一次灰煙 | `board_need_fish`、`board_need_knife`、`board_finish_knife`、`jar_need_fish`、`jar_need_salt`、`jar_wrong_fish`、`jar_paste_fresh`、`tank_not_fish`、`tub_what`、`pond_what`、`rack_empty_hand`、`rack_other_kind`、`auger_no_water`、`icehole_use`、`pond_salt`（鹽不夠） |
| **還沒好** | 正在做，等時間 | `random.click`，音高 0.6，兩下 | 方塊上冒一個白色小氣泡 | `jar_fermenting`、`jar_salted`、`rack_drying`、`tub_busy`、`tub_soaking`、`tub_hatching`、`trap_baited`、`pond_salted` |
| **滿了** | 沒有空間 | `random.splash`（有水的方塊）或 `dig.wood`（其他），音高 1.4 | 東西從方塊上彈回來的掉落粒子 | `rack_full`、`tank_full`、`tub_full`、`tub_clams_full`、`pond_feed_full`、`tipup_limit` |
| **這裡不行** | 位置或環境不對 | `dig.stone`，音高 0.5 | 放下的位置冒紅色塵土（`minecraft:redstone_wire_dust_particle`） | `salt_pan_place`、`pond_has_feeder`、`board_pack_gone`、`tank_pack_gone` |

- 原因到類別的對照寫在 `util/hint.js` 的一張表裡；新的原因沒有歸類就讓測試失敗。
- 每位玩家 10 刻一次的節流照舊。
- 只有自己聽得到的照舊（`player.playSound`）；粒子是大家都看得到的，量很小。

### 12.3 做法

- **方塊不能直接播動畫**：基岩版的自訂方塊沒有動畫，會動的部分改用只負責外觀的實體疊在方塊上（1.5.0 的魚缸、魚池已經這樣做）。
- **只在看得到時才有**：外觀實體只在方塊運作中、且 16 格內有玩家時生成；玩家走遠就移除；區塊載入時清掉沒有對應方塊的殘留。同時存在的外觀實體設上限，超過時方塊照常運作、只是不播動畫。
- **粒子節流**：每個方塊每幾秒最多一次，只在 16 格內有玩家時發出。
- **可以關閉**：手帳設定頁加一個開關（齒輪圖下的「動畫」圖示），給效能較弱的伺服器用。

## 20. 測試

沿用 `python tools/run_tests.py`。

**新增的檢查**

- 無字檢查（4.4）：腳本、實體檔、語言檔。例外清單在步驟 15 時只能剩收線小遊戲。
- 字元表：每個 `GLYPHS.json` 的名稱都有對應的圖格；沒有兩個名稱用同一格；每種魚、每道料理都有字元。
- 拒絕：每個 `refuse` 的原因都在四類之一。

**新增的模擬遊玩**

- 手帳：每一頁的標題、內文、按鈕只有字元與空白；魚種頁的圖示和 `CATCHES.json` 一致（水域、時段、天氣、潮汐、月相、天象）；釣過次數的點數；外部的魚用通用魚影或 `like` 的字元。
- 食譜：102 道的「鍋具 ＋ 食材 → 料理」和 `KC_RECIPES.json` 一致。
- 魚池：撈網撈到的是對應位置的那條魚；池子變動中撈網的對象已經不在時什麼都不做；空手取魚卵與點名；食槽 4 段的界線；餓的魚的狀態切換。
- 魚簍：5 段外觀的界線（0、1、16、17、40、41、63、64）；圖示格只有字元與尺寸記號、底色的界線（8、9、32、33）；點一格取出的是那一種；蹲下倒出全部；換 ID 時內容與附魔不變；舊存檔的魚簍讀得出來。
- 紀錄：舊的「★ N cm」轉成動態屬性；新的魚只有 ★；魚拓依長度縮放。
- 漁販：木牌的數量和訂單進度一致；新魚出現在想收；錢袋空了不收但訂單照收。
- 外觀實體：玩家走遠就移除；區塊載入時清掉殘留；上限。

**遊戲內檢測表**（`docs/TEST_CHECKLIST_1.6.md`）

字元的大小與清晰度（尤其是手機）、手帳兩種做法的樣子、撈網好不好瞄準池裡的魚、魚簍五段外觀、四類拒絕聲音分不分得出來、漁販的木牌與動畫、各方塊的動作、環境聲的音量、和森羅廚房與家族一起裝時字元與表單外觀有沒有被蓋掉。

## 21. 風險與保底

| 風險 | 影響 | 保底 |
| --- | --- | --- |
| 字元頁被原版或其他附加包占用 | 手帳與說明顯示成別的圖 | 步驟 4 先確認；撞到就整體換一頁。字元的碼位只寫在 `GLYPHS.json`，換頁只改一處 |
| 自訂表單外觀和其他附加包衝突 | 手帳或其他附加包的表單變形 | 用做法 B（原版表單） |
| 手機上字元太小 | 手帳看不清楚 | 字元表做成 32×32 一格的高解析版本（基岩版的字元表可以用更大的圖）；手帳每頁放的少一點 |
| 撈網瞄不準池裡的魚 | 撈不到想要的魚 | 撈網對水面使用時，撈起離準心最近的那一條 |
| 拿掉清單後，玩家不知道池裡的魚何時長大 | 少了資訊 | 長大時的翻身與水花；第 14.1 節的魚拓（定案不畫天數小點，見第 22.2 節第 4 項） |
| 外觀實體太多拖慢伺服器 | 卡頓 | 16 格內才生成、數量上限、設定頁可以關 |
| 魚簍換物品 ID 時遺失內容 | 魚不見 | 內容存在動態屬性，換 ID 前先複製；測試逐條比對 |
